# weragen-site

Лендинг weragen, открытой платформы для ИИ-автоматизаций. Статический сайт на Astro,
публикуется на GitHub Pages: <https://egsp.github.io/weragen-site/>.

В ветке `feat/landing/codex-redesign` подготовлены три чёрно-белых варианта лендинга.
У каждого собственные тексты и композиция.

- Статья объясняет, какую повторяющуюся работу берёт на себя платформа. Раздел о моделях выделен тёмным фоном
- Разработчикам описывает подключение через API, показывает пример запроса и границу ответственности приложения и платформы
- Платформа сохраняет широкую композицию третьего первоначального варианта со схемой. Мелкие подписи, нумерация, иконки, стрелки и рамки убраны

Переключатели сверху меняют вариант и шрифт без перезагрузки. Доступны IBM Plex Sans
и Golos Text с обычным и жирным начертаниями. Шрифты поставляются вместе с сайтом.
По умолчанию открыт вариант Платформа. Без JavaScript доступен он же.

В каждом варианте три содержательных раздела. Тексты основаны на ответах в разделах 1-3
`docs/вопросы_2.md` из ветки `docs/product/questions` репозитория `EGSP/weragen`.
IBM и OpenTUI послужили исходными ориентирами. Оформление переработано по замечаниям
пользователя. На странице нет декоративных иконок, стрелок, номеров секций и мелких подписей.
Схема и пример запроса иллюстрируют концепцию, а не работу подключённого сервера.
Продукт обозначен как находящийся в разработке; готовность будущих SDK и функций не обещается.

## Локальное сравнение

Работа Codex находится в `.worktrees/codex`. Из этого каталога:

```bash
npm install
npx astro dev --background --port 4332 --host 127.0.0.1
npx astro dev status
npx astro dev stop
```

Адрес: <http://localhost:4332/weragen-site/>. Выбор сохраняется в параметрах адреса:
`version=1`, `version=2` или `version=3`; `font=ibm` или `font=golos`.
Например: <http://localhost:4332/weragen-site/?version=2&font=golos>.
Кнопки браузера Назад и Вперёд восстанавливают выбор. Ссылки на разделы работают
в каждой версии. Переключение вариантов требует JavaScript.

Перед переработкой первоначальное состояние сохранено коммитом `8f091fd` и отправлено
в `origin/feat/landing/codex-redesign`. Дальнейшие изменения ведутся в этой же ветке.
Ветка не сливается с `main`, публикация не запускается.
Панель разработчика Astro скрыта, чтобы не мешать просмотру.

## Устройство

| Путь | Назначение |
|---|---|
| `src/pages/index.astro` | страница, переключатели версии и шрифта |
| `src/components/ArticleLanding.astro` | редакционный вариант |
| `src/components/DeveloperLanding.astro` | вариант для разработчика |
| `src/components/PlatformLanding.astro` | вариант со схемой платформы |
| `src/components/Hub.astro` | схема связей платформы |
| `src/styles/landing.css` | оформление и адаптация к узким экранам |
| `public/favicon.svg` | значок сайта |
| `astro.config.mjs` | адрес сайта и каталог публикации |
| `.github/workflows/pages.yml` | сборка и публикация |
| `AGENTS.md` | правила для агентов: ветки, worktree, сервер разработки |

## Команды

```bash
npm install
npm run dev        # сервер разработки: http://localhost:4321/weragen-site/
npm run check      # проверка типов
npm run build      # сборка в dist/
npm run preview    # просмотр собранного сайта
```

Требуется Node.js 22.12 или новее; CI использует версию из `.nvmrc`.

## Публикация

Workflow `.github/workflows/pages.yml` запускается в трёх случаях:

- push в `main`: проверка типов, сборка и публикация на GitHub Pages;
- pull request: проверка типов и сборка без публикации;
- ручной запуск на `main`: повторная публикация.

В настройках репозитория источник Pages: **GitHub Actions** (Settings → Pages → Source).

Для собственного домена в `astro.config.mjs` меняется `site` на адрес домена и удаляется
`base`, домен указывается в Settings → Pages → Custom domain, а у регистратора добавляется
DNS-запись по инструкции GitHub.
